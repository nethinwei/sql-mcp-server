# v0.1.12

`v0.1.12` 让管理面在大库和长期运行下可用，并解决同名表的命名问题：元数据扫描与
控制台导入不再随表数线性变慢；热重载改为发布后排空，新旧快照共享连接池、IO 配额
与读缓存，除传输方式、监听地址与 TLS 开关外的配置都可热加载；实体改为命名空间
身份 `数据源.库.名称`。

本版本包含 breaking 变更，升级前请先阅读[迁移](#迁移)。

## 元数据扫描与导入

- 自省按 schema 批量读取元数据（参考 mysqldump），往返次数与表数无关；本地 600
  张表：PostgreSQL 0.98s → 58ms，MySQL 1.32s → 18ms。连接权限探测按 schema 批量，
  在发布后后台执行，不阻塞启动与重载。
- 控制台导入改为“库 → 表”：展开库时才扫描，扫描是有界、可取消、限时的后台任务，
  结果保留到下次重新扫描。导入页按各数据库自己的术语列出全部索引（结构、键部分、
  表达式原文、部分索引条件）；OceanBase 表达式、全文与空间索引经 `SHOW INDEX`
  解析为真实列。
- MySQL/OceanBase 成本闸门遍历整棵 `EXPLAIN` 计划树，带过滤的聚合与连接不再被误判
  为“未知扫描”。

## 运行时协调与热重载

- 发布后排空（publish-then-drain）：新快照立即生效，旧快照在其在途请求结束后于后台
  关闭；待回收快照最多 3 个。
- 新旧快照共享连接池（设置未变不重连）、IO 配额与限流熔断、读缓存。读缓存按物理
  数据库失效，旧快照的写入同样使新快照的缓存失效，带失效戳防止回填旧值（TM-007）。
- 可热加载：工具集合与 custom procedure tool（客户端收到 `tools/list_changed`）、
  认证（token、可信代理、用户启用与删除）、TLS 证书与客户端 CA 轮换、事务
  `ttl`/`maxOpen`。被吊销用户的会话在发布时关闭，按会话 ID 回滚，重新启用后新建的
  会话不受影响。
- 显式事务绑定开启时的连接：重载把数据源改到别的连接后，事务内后续语句返回
  `TRANSACTION_STALE`，只能回滚。自动提交与事务提交共用写入后处理，级联写到同库其他
  数据源后，会话经这些数据源的读取同样走写连接。

## 实体命名空间

- 实体按 `数据源.库.名称` 识别，名称默认取表名，只需在同一数据源与库内唯一；不同
  数据源或库的同名表各自是同名实体，不再需要前缀。
- 授权、关系、`affects` 与 Agent 调用的 `entity` 写 `名称`、`库.名称`、`数据源.名称`
  或完整 ID，必须恰好对应一个实体。配置中有歧义的引用使发布失败，因此新增实体不会
  悄悄改变已有引用的指向。
- Agent 只在自己能访问的实体中解析引用；歧义时返回 `AMBIGUOUS_ENTITY`，
  `constraints.candidates` 列出无歧义写法，调用方不能访问的实体不计入、不列出。
  describe 与授权 schema 资源给出最短无歧义名与 `id`。
- 控制台按 `数据源 · 库` 分组显示实体，名称与表名不同时才显示表名；新增、改名或移动
  实体使已有引用产生歧义时自动改为限定写法。CLI `add entity` 新增 `--schema`。

## 迁移

完整列表见 [CHANGELOG](../../CHANGELOG.md) 的 0.1.12 Breaking 段。要点：

- **实体名不得含点**，数据源名、库名同样；现有配置的实体名全局唯一，引用无需修改。
- **过程工具名后缀变化**：哈希改为对规范 ID 计算，硬编码了 `procedure_<名称>_<哈希>`
  的客户端需按 `tools/list` 更新。
- **describe / schema 资源的 `name`** 为最短无歧义写法并新增 `id`；审计、能力报告与
  权限模拟按规范 ID 标识实体，依赖实体名做审计检索的需改用 ID。
- **管理 API**：移除 `schemaImport`，改用 `schemaList`、`schemaTables`、
  `startSchemaScan`、`schemaScan`、`cancelSchemaScan`。
- **新错误码** `AMBIGUOUS_ENTITY`（可重试）与 `TRANSACTION_STALE`（不可重试）。
- 构建要求 Go 1.26.9；Go API 变化见 CHANGELOG。

## 已知限制

- 管理面 2（Trusted SQL Escape Hatch，`execute_sql`）未交付，顺延到 `v0.1.13`。
- 传输方式、监听地址与 TLS 开关的变更仍需重启。
- 数据源名与库名相同时（如 OceanBase 的 `ledger` 库），`数据源.名称` 与 `库.名称`
  是同一写法，同数据源另一库中的同名实体会使其产生歧义，需要写完整 ID 或另起实体名。
- OIDC / 通用 OAuth2 登录与控制台交互判据的外部实测仍未完成（同 v0.1.11）。
