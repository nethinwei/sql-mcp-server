# v0.1.14

`v0.1.14` 交付管理面 2：可信 SQL 逃生通道 `execute_sql`。可信操作者（DBA、排障、临时
分析）得到一个受审计、受硬上限约束的任意 SQL 入口，不再需要绕过本服务直连数据库；
受治理面不变，不接受任意 SQL 的边界只对受治理面声明。设计与评审决议见
[设计文档](../design/sql-escape-hatch.md)。

本版本没有 breaking 变更。

## 可信 SQL 逃生通道

- 工具 `execute_sql` 默认不注册。可见与可用须同时满足：`tools.executeSql: true`、调用
  用户持有 `sql:execute@<数据源>`（角色 `permissions` ∪ 用户直授；本版唯一支持的系统
  权限）、数据源声明 `sqlEscape: {connection: <连接名>}`。缺一即 `UNAUTHORIZED`，
  `tools/list` 按用户过滤，列表不是安全边界。
- 语句在声明的连接上原样执行、自动提交：不解析、不改写、不脱敏；连接账号的数据库
  权限就是上限。`query` 返回 `columns`/`rows`/`rowCount`/`truncated`（到行上限即截断），
  `exec` 返回 `rowsAffected`。不接受事务令牌，不进读缓存；执行后整库失效读缓存。
- 硬上限不可关闭：`cost.queryTimeout`、`cost.maxRows`、`cost.maxBytes`、预算、限流与
  熔断复用受治理面的链路。估算策略 `cost.sqlEscape.estimate`：`required`（默认）在逃生
  通道连接上 EXPLAIN 并按闸门阈值打分，EXPLAIN 不接受的语句一律拒绝；`skip` 只保留硬上限。
- 审计 fail closed：开启 `tools.executeSql` 要求 `audit.enabled`；执行前后各写一条同步事件
  （`phase: begin/end`、`datasource`、`connection`、`sql` 原文、`rowsAffected`、
  `action: sql`）；`begin` 写入失败不执行，`end` 写入失败不返回结果（新拒绝码
  `AUDIT_UNAVAILABLE`）。
- 契约例外：本工具的 `DATABASE_ERROR` / `DATASOURCE_FORBIDDEN` 回显驱动原文与
  `constraints.sqlstate`。
- 新增不变量 I29、威胁 TM-013（`internal/threatcheck/coverage.json` 映射 14 个测试）。

## 管理面

- GraphQL：`Role.permissions`、`User.permissions`（输入同名）、`Datasource.sqlEscape`。
- 工作区项 `RoleItem` / `UserItem` 新增 `permissions`；控制台角色与用户页的“系统权限”
  区块（只列出声明了 `sqlEscape` 的数据源）、用户页与模拟页显示 `execute_sql` 可用的
  数据源、数据源摘要显示逃生通道连接。

## 迁移

- 无需操作。不配置 `tools.executeSql` 与 `sqlEscape` 时行为与 v0.1.13 一致。
- 工作区项形状变化：已保存的服务端工作区在升级后会读作“已修改”（`permissions` 字段
  出现在每个角色与用户项中），在控制台 reset 或直接提交即可。
- 路线图文案：管理面 4 已随 v0.1.11 交付，OIDC / OAuth2 登录待排期。

## 已知限制

- 逃生通道的权限上限等于连接账号的数据库权限，与 `routing` 共用账号时等于受治理面
  写账号；建议独立账号。
- 数据库错误原文回显给调用方并进入代持令牌的 Agent 上下文。
- 服务不解析 SQL，驱动层接受的多语句无法禁止；审计记录整段文本。
- `end` 事件写入失败时 `exec` 的效果已发生，调用方需自行确认。
- 只改权限的热重载不发 `tools/list_changed` 通知，客户端下一次 `tools/list` 才看到变化；
  调用立即被拒。
- 估算按闸门阈值打分，无键的全表 UPDATE 会被软拒绝；MySQL / OceanBase 连接默认的
  `sql_safe_updates=1` 也会拒绝无键写入，需要时在逃生通道连接的 DSN 中显式设置。
- OIDC / 通用 OAuth2 登录与控制台交互判据的外部实测仍未完成（同 v0.1.11）。
