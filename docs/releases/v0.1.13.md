# v0.1.13

`v0.1.13` 把管理面做成多管理员、多副本、可由 Agent 协作的工作方式：配置以方案
批量生成，工作区保存在服务端并三方合并，发布只允许快进；所有触达数据库的执行与
后台任务经执行总线准入；配置分为意图与生效值；数据面改为固定管线。随版本一起落地
两轮代码整理，内部结构与依赖方向更清楚，行为不变。

本版本包含 breaking 变更，升级前请先阅读[迁移](#迁移)。

## 执行总线

- `core/bus`：工具调用、管理读取、扫描与后台任务按通道准入并共享
  `rateLimit.ioPool`，非工具调用通道合计至多占一半；
  `execution.{admin,scan,background}.{maxConcurrent,maxQueue}` 可热重载。
- 所有后台 goroutine 与定时器经总线登记、恢复 panic 并在关闭时排空
  （`internal/buscheck` 强制）；热重载期间新旧快照共享 `maxInflight`。
- OTel 指标 `smcp.bus.*`、GraphQL `serverStatus.execution` 与控制台概览页的
  “执行资源”卡片。

## 批量配置

- 扫描结果与扫描批次保存在配置库（schema 版本 3/4），重启与多副本共享；批次在
  服务端逐库进行，所有者停止心跳后由其他进程接管，每库按“所有者 + 当前状态”条件
  写入，失败的库退避重试，配置库故障时重试写入并读回确认；每个数据源最多 4 个
  未完成批次、每批最多 5000 个库。租约、心跳、接管与重试在 `x/leasing`，交错模型
  测试锁定其不变量。
- 方案引擎 `x/configplan`：按范围与规则（导入、授权、字段隐藏/脱敏、同步字段）生成
  方案，报告涉及对象、依据的扫描、合并后的变化与三级例外；控制台导入、“按规则配置”、
  模板与配置 MCP 共用；方案模板带版本与修改记录，“重复执行”的模板进入“待处理”。
- 配置 MCP `/admin/mcp`：每个客户端一个管理员令牌（命名、有效期、吊销、可限定
  数据源），检索目录、扫描库、预览方案、按预览标识写入工作区；不提供发布工具。
- 目录共享索引：每张表的状态与差异只算一次，翻页每页分配从约 10 MB 降到 0.6 MB。

## 服务端工作区与版本管理

- 版本管理成为独立模块（`core/workspace` + `x/workspaceops`）。工作区每人一份，
  保存在服务端（`smcp_workspaces`，schema 版本 5），任何控制台与管理员的 Agent 都
  写这一份；按项写入带上读到的值，期间别处写过则三方合并，同一处改得不同成为冲突，
  不丢任何一方。update、reset、合并草稿、解决冲突、检查点与提交都是服务端操作。
- 发布只允许快进：草稿必须基于当前已发布版本，否则 `CONFLICT`；两个管理员几乎
  同时发布时后提交的一方得到最新版本号以便变基。`/admin/events`（SSE）推送新发布、
  工作区写入与草稿列表变化。
- 编辑领域收归服务端：工作区项的类型与编解码只在 `x/admin/configapp`，改名与删除
  引起的引用维护由服务端 `Reconcile` 完成；目录、方案预览、校验、diff、模拟默认读
  调用者的工作区；diff 在生成前结构化脱敏。
- 控制台：多管理员发布、待审草稿、网关路径前缀（`server.pathPrefix`）、客户端接入
  配置（`server.publicURL`）、导入页重做。

## 配置、生命周期与数据面

- 配置分为意图（`config.Spec`，只记录写了什么）与生效值（`config.Config`）：配置库
  只存写过的值，旧 payload 逐字节兼容；管理面只以 Spec 作内存表示。
- 进程级状态（连接及其熔断/自适应并发、事务、预算、写跟踪、缓存、结果内存）归
  `bootstrap.Shared`，重载不搬运状态；熔断与自适应并发按数据库连接隔离；新增
  `transactions.maxOpenPerConnection`。已发布版本能加载但装配失败时，它改动的用户
  立即暂停。
- 数据面固定管线：数据库只由执行器调用，语句须由授权结果与过闸 SQL 构成（结构
  测试强制）；结果逐行计量，越过 `cost.maxBytes`/预算的第一行即中止；新增
  `rateLimit.maxResultMemory`。新增错误码 `OUTCOME_UNKNOWN`，事务结束后 10 分钟内
  再用令牌得到 `TRANSACTION_NOT_FOUND` 附 `constraints.outcome`。
- 成本闸门：`cost.fullScanMaxRows`（默认 1000）放行小表全扫描，表的行数取自表的
  规模；MySQL 执行前判定不读表的计划按点查处理。

## 代码整理

- 去重与热路径：`internal/kit`、`entity.ParseAction`、`config.ParseFilter`、
  `revision.BasedOn` 各一份实现；`tool.Context` 拆为每次调用字段与共享 `*Services`；
  授权器按实体预编译；谓词每条语句只校验一次。
- 装配与基础设施：装配入口收敛为一个 `assembly`；`sqladapter.Base`/`Scanned` 为
  三个 provider 共用；配置库行扫描与加锁事务泛型化；测试替身出核到
  `storetest`/`costtest`；`core/tool` 错误包装统一。
- 指标：`/metrics` 由 OpenTelemetry 指标经 Prometheus exporter 提供，指标名、标签与
  分桶不变。
- GraphQL 配置读模型直接绑定工作区项类型，`x/admin/graph` 不再维护自己的转换器。

## 迁移

完整列表见 [CHANGELOG](../../CHANGELOG.md) 的 0.1.13 Breaking 段。要点：

- **发布只允许快进**：此前可直接发布的旧草稿需在工作区审核（自动合并到最新发布）
  后再提交。
- **租户并发限额按租户聚合**（所有会话、所有主体合计）；**新增
  `transactions.maxOpenPerConnection`**，默认 `max(1, rateLimit.ioPool/2)`，需要原
  行为时设为 `rateLimit.ioPool`。
- **管理 API**：`ServerStatus.pending` 改名 `unapplied`；移除 `DraftInput` 与
  `createDraft`，查询的 `draft` 参数改为 `revision`；配置读模型改为与工作区项同一
  形状（如实返回、未设置即 null），移除 `Entity.id`、`Role.members`、`User.hasToken`。
- **Go API**：`relalg.IsNull` 并入 `Condition`；`engine.Submit`/`engine.Run` 为泛型
  包级函数；`mcpserver.HTTPConfig` 的鉴权字段在嵌入的 `HTTPAuth`；`store.Fake*`、
  `cost.Fake*` 移至 `storetest`/`costtest`。
- 升级前浏览器中保存的工作区不再自动归属：有未发布修改时提示，由管理员确认恢复或
  丢弃。
- 构建要求 Go 1.26.9；golangci-lint v2.12.2。

## 已知限制

- 管理面 2（Trusted SQL Escape Hatch，`execute_sql`）未交付，顺延到 `v0.1.14`。
- Hologres provider 未随本版本合入：其分支基于 `v0.1.11` 之前的能力模型，需按当前
  `dialect.Capabilities` 与 `sqladapter` 骨架重做。
- 传输方式、监听地址与 TLS 开关的变更仍需重启。
- OIDC / 通用 OAuth2 登录与控制台交互判据的外部实测仍未完成（同 v0.1.11）。
