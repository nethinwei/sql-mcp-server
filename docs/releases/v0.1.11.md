# v0.1.11

`v0.1.11` 交付管理面第一批能力：**用户、角色与权限**（管理面 1），以及
**配置存储与 revision**（管理面 3）、**管理 API 与 schema 导入**（管理面 4）和
**管理控制台**（管理面 5）的核心路径；同时落地[数据源模型](../design/datasource-model.md)
（物理身份、身份键与级联、多连接路由、连接权限感知）。设计见
[授权模型](../design/authorization-model.md)、[配置存储](../design/config-store.md)、
[管理 API](../design/admin-api.md)。

本版本包含 breaking 变更，升级前请先阅读[迁移](#迁移)。

## 用户、角色与权限

- 顶层 `roles`（授权项 grants：实体、动作、可读/可写字段、行范围）与 `users`
  （每用户 `tokenHash`、多角色、直授 grants、固定 subject、`disabled`）；实体
  `tenantPolicy` 是对所有主体始终 AND 的租户硬边界。
- 多角色按请求选择覆盖其全部字段的授权项，行范围在这些授权项之间取 OR；不存在
  单一覆盖时返回 `AMBIGUOUS_FIELD_SCOPE`。字段与行不分别取并集，合并不会授予任一
  授权项都没有的“字段 × 行”组合（TM-009）。
- HTTP 每用户 bearer 认证与可信代理 `X-MCP-User`；热重载删除或禁用用户时解除其
  会话并回滚在途事务（TM-010）。审计记录 `user`、`roles`、`grants`。
- 未配置 `users`/`roles` 时行为与之前等价。

## 配置存储、管理 API 与控制台

- `serve --store <driver>:<dsn>` 从 SQLite、PostgreSQL、MySQL 或 OceanBase 中的
  已发布 revision 启动，`--watch` 热重载；`store init/import/list/show/diff/publish/
  rollback` 与 `migrate` 子命令。发布带乐观并发检查，与文件 reload 共用热重载守卫。
- `serve --store ... --admin` 挂载 GraphQL 管理 API 与嵌入二进制的 Vue 控制台：
  数据源导入（零权限草稿）、权限矩阵、可见范围预览与权限模拟、发布审查（授权规则
  变化、重启提示、权限告警）、版本历史与回滚、其他设置编辑器。
- 本地管理员账号（argon2id，`sql-mcp-server admin` 引导首个账号），会话 Cookie +
  CSRF，登录全局限并发，改密吊销该账号的全部会话。
- 配置规则单一来源：字段类型、约束、默认值与“修改需重启”标记定义在
  `core/config` 结构体标签，生成 `schema.json` 与配置文档，控制台与 CLI 共用。

## 数据源模型

- **物理身份**：一个物理表或视图最多对应一个实体（I-1），跨数据源按服务器身份与
  大小写规则识别；视图与 PostgreSQL 物化视图可作为实体（修复 `kind: view` 启动即报
  缺失）；缓存按物理关系失效，指向同一物理库的数据源一并失效。
- **身份键**：主键与唯一键以数据库为准；能唯一定位一行的唯一键（部分索引、表达式
  索引、前缀索引与含可空列的键除外，INCLUDE 列不计入键）可用于写保护与游标分页；
  视图上声明的键只用于读。
- **级联**：外键 `CASCADE`/`SET NULL`/`SET DEFAULT` 要求调用方对级联链上每一层的
  实体拥有不带行范围、覆盖被改写外键列的权限（I-6），`allowCascade: true` 显式放开。
- **多连接路由**：一个数据源可配置多个连接（只读账号、读写账号、副本），读、写、
  执行按 `routing` 分别路由；`readAfterWrite` 让会话写入后一段时间内读走写连接并
  绕过共享缓存；`pooler: transaction` 支持事务模式连接池。
- **连接权限感知**：启动与重载时探测路由连接的表级、列级、过程权限与只读状态；
  授权超出连接能力时告警（不阻断发布），控制台权限矩阵置灰并提示原因。
- 新拒绝码 `CONSTRAINT_VIOLATION`（retryable，只给类别与可见字段）与
  `DATASOURCE_FORBIDDEN`（不可重试，不计入熔断）；`describe_entities` 与
  `sql-mcp://schema` 增加 `datasource`、`required`、`readOnly` 与可见身份键（兼容变化）。

## 迁移

完整列表见 [CHANGELOG](../../CHANGELOG.md) 的 0.1.11 Breaking 段。要点：

- **配置未知字段直接拒绝加载**：升级前运行 `sql-mcp-server validate`。删除
  `rateLimit.cpuPool`，把 `budget.*.maxScannedRows` 改名为
  `maxEstimatedScannedRows`。
- **同一物理表只能有一个实体**：此前为只读、读写两个 DSN 各配一个实体的，保留
  一个实体，改用同一数据源的 `connections` 与 `routing`。
- **键以数据库为准**：在无主键约束的表上声明 `primaryKey` 不再让修改和删除通过写
  保护；需要时在数据库中补主键或唯一约束。
- **级联写入默认受检**：有级联外键的父实体，删除/修改调用方需要子实体权限，或为
  父实体设置 `allowCascade: true`。
- MySQL/OceanBase 未设 `schema` 的实体解析到连接的当前数据库；DSN 未指定数据库时
  为实体设置 `schema`。
- `read_records` 的 `cursor` 必须是游标键前缀，`offset` 必须与 `limit` 同时给出。
- 最低 Go 版本 1.26；Go API 变化（`providerregistry.Options`、`tool.DataSource`
  按动作拆分连接等）见 CHANGELOG。

## 已知限制

- 管理面 4 只交付本地账号登录；OIDC / 通用 OAuth2 登录未交付。
- 管理面 5 的交互判据（新用户 ≤ 5 分钟、≥50 张表 ≤ 15 分钟）尚无外部试用者实测
  记录。
- 管理面 2（Trusted SQL Escape Hatch，`execute_sql`）未交付，仍在路线图中。
- MySQL 触发器与例程级授权的权限探测结果为“未知”；pgbouncer 事务模式与
  PostgreSQL 流复制副本没有容器测试，路由由同库两个账号的集成测试覆盖。
- 分库分表、每租户一个 schema、跨库事务、PG 函数与 OUT 参数不支持（见数据源模型
  设计的边界核对）。
