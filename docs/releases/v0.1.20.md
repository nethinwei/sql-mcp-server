# v0.1.20

`v0.1.20` 是一个加固版本。起因是一次外部代码与设计 review：它确认了数据面的核心边界成立
（受治理面没有任意 SQL、注入或授权绕过），同时指出了以下问题：

- 一个可复现的进程崩溃（审计关闭竞态）；
- 一个多租户写入缺口（create 不应用租户策略）；
- 若干配置校验与一致性缺陷；
- 若干在压力下无界或 O(n²) 的结构。

本版本逐条处理了这些结论（见 [Review 处理](#review-处理)），并按用户需求在控制台加入“同步
实体”。原计划随 SQLite 交付的三项改进也在本版本交付：

- MySQL 写超时在数据库侧强制；
- 只读账号不告警写超时；
- 服务端原因文本本地化。

Evidence-Backed SQLite 本身顺延到 `v0.1.21`。

本版本**有 breaking 变更**，见[迁移](#迁移)。

## 安全

- **写入受行范围约束（WITH CHECK）**：create 插入的行、update 修改后的行，都必须仍在调用方
  的行范围内（租户策略 AND 授权项行范围），语义与 PostgreSQL 行安全策略的 `WITH CHECK` 相同。
  - **create**：行范围以等值固定的列（通常是不对 Agent 暴露的租户列）在调用方未提供时，
    由服务端按该值填入（与 Hasura 的 column preset 同理）。调用方提供的值使行越界时，返回
    新拒绝码 `ROW_POLICY_VIOLATION`；
  - **update**：把新值代入行范围。必然越界的直接拒绝；其余情况把剩余条件并入 WHERE。
  - 此前 create 不应用租户策略与行范围，获授 create 的调用方可以插入其他租户的行；update 可以
    把行改到其他租户。见 TM-015、I30。
- **主键默认不可修改**：`update_record` 修改主键（无主键时为第一个可标识行的唯一键）默认拒绝，
  实体设置 `allowKeyUpdate: true` 才允许。codegen 层拒绝无谓词的 UPDATE/DELETE 和不赋值的
  UPDATE，作为工具层之外的最后防线（I31）。
- **写工具默认关闭**：省略 `tools` 时，`create_record`、`update_record`、`delete_record` 都不
  注册。此前前两个默认注册。实体的 `mcp.dmlTools` 仍只决定实体是否参与通用工具。
- **mTLS 证书映射到用户**：新增 `users[].certSubjects`（`cn:`、`dns:`、`uri:`（如 SPIFFE
  ID）、`email:`）。配置了用户时：
  - 不带 bearer token 的直连证书，必须匹配某个用户，否则返回 401；
  - `server.auth.tls.clientIdentity: default` 可以恢复此前的行为（使用默认身份）；
  - 受信代理的证书不受影响，带 token 的请求以 token 为准。
- **共享 token 强度**：监听非 loopback 地址时，`server.auth.token` 至少 32 字节。`transport: http`
  的配置校验时检查一次，启动时再按实际监听地址检查一次（`--transport`、`--addr` 可能与配置不同）；
  stdio 不监听，不检查。
- **`X-MCP-Subject` 取值收紧**：
  - 属性值只能是字符串、整数、布尔，或由它们组成的列表；对象和嵌套列表返回 400；
  - 整数按 int64 取值，与配置中的同名属性一致，避免同一租户得到不同的缓存与 singleflight 键。
- **脱敏不再泄露长度**：`phone`/`idcard` 中间固定为 `****`，按字符处理：
  - 11 位及以上保留前 3 位和后 4 位；
  - 8–10 位保留前 2 位和后 2 位；
  - 不足 8 位整体为 `***`。

  此前星号数等于被遮字符数，且多字节文本可能被截成非法 UTF-8。
- **`execute_sql` 估算 fail closed**：`estimate: required` 但没有 EXPLAIN 可用时，不再静默跳过：
  - `cost.enabled: false` 且开启了逃生通道时，配置校验失败；
  - provider 不支持 EXPLAIN 时，装配失败；
  - 执行时没有 explainer，返回无法估算。

## 修复

- **审计关闭竞态**：`Record` 先检查是否已关闭、再发送，`Close` 可能在两步之间关闭队列，
  导致进程 panic（send on closed channel）。关停时排空超时、仍有在途调用写审计时会发生。
- **配置校验**：行过滤的每一层必须恰好是一个条件、非空的 `and`/`or` 或 `not`，并新增了
  `not`。以下情况在加载时即拒绝：未知键、空 field、非法 `in`、条件引用了字段别名。此前这些
  配置能通过校验，到第一次查询时才失败，例如 `{and: []}`。另外：
  - `FilterOf` 与 `ParseFilter` 可以往返；
  - 行过滤引用的列（可以不是字段）在装配时检查是否存在，缺失时按缺列让实体不可用；
  - 同一实体内，字段名与别名不能指向两个字段，此前会解析到先出现的那个，脱敏规则也会错配。
- **行过滤 `in` 列表中的占位符**：`in: ["${subject.region}", "global"]` 中的占位符此前不会
  被解析。现在列表属性展开为多项，缺失的属性为 NULL。
- **数字精度**：带小数点或指数的 JSON 数字不再转为 float64。按列类型处理：
  - 浮点列转为 float64；
  - 整数列收到小数时返回 `INVALID_INPUT`；
  - numeric、decimal 与类型未知的列，以原文字传给驱动；
  - `execute_sql` 的参数同样以原文字传递。
- **扫描量未知的全表扫描**：provider 没测出表行数时，全表扫描的读取行数视为未知。设置了
  `cost.maxScannedRows`（默认 10 万）或预算 `maxEstimatedScannedRows` 时硬拒绝，拒绝的
  `constraints` 中给出 `scannedRowsUnknown: true`。此前按输出行数计，扫描上限形同虚设。
- **成本链诊断**：软拒绝返回整条链最终的 Plan、分数与 Bypass，提示合并去重。此前返回的是
  软拒绝那一层的快照。
- **写入与过程结果内存**：结果超过 `rateLimit.maxResultMemory` 时，停止保留后续行，返回
  `"truncated": true` 并写审计；写入已生效，调用不失败。此前强占内存，可能导致 OOM。
- **关系展开**：
  - 整数、浮点、decimal 文字形式的连接键按数值匹配，例如 `12.50` 与 `12.5000` 匹配；此前会
    静默匹配不到子行；
  - 没有连接列的关系返回 `INVALID_INPUT`，此前会除零。
- **写后读隔离**：会话的写入只在数据源的 `readAfterWrite` 窗口内隔离它的读取：
  - 窗口过后恢复跨会话共享结果，未配置窗口的数据源不再记录写入；
  - `readAfterWrite` 上限为 1 小时；
  - 此前写过一次就永久隔离，记录也不清理。
- **配置存储**：
  - `smcp_store_meta` 的锁行或计数行缺失时，写入返回 `store is corrupt`，不再在没有锁的情况下
    继续；
  - schema 版本 6 由数据库约束保证至多一个 published revision；已存在多个时迁移中止，并列出
    它们与修复语句；
  - `store init` 中途中断后可以重新运行，MySQL/OceanBase 中断的迁移重新打开即可继续。
- **控制台**：只包含“删除实体”的方案此前被判为无变化，无法应用。

## Provider 与数据库侧限制

- **MySQL 写超时在数据库侧强制**：直连 MySQL 时，写语句、存储过程与 `execute_sql` 到了请求
  截止时间，会经另一条连接执行 `KILL QUERY <该连接的线程号>` 停止并回滚，行锁随即释放，与
  PostgreSQL 在超时时发送取消请求对等。
  - `limit.timeout.write` 由 unsupported 改为 enforced；
  - 开启逃生通道的 MySQL 数据源不再告警，在 `cost.requireNativeLimits` 下也能加载。

  实现细节：
  - 每条连接建立时读一次 `CONNECTION_ID()`；
  - 线程号在服务器运行期间不复用，迟到的 KILL 只会落空；
  - 发过 KILL 的连接不再复用；
  - KILL 走独立的小连接池，限时 2 秒，失败只记日志；
  - 同一账号停止自己的线程，不需要额外权限。

  经事务型连接池（`pooler: transaction`）时不发送 KILL（线程号属于池借出的会话，可能误停其他
  客户端的语句），写超时仍为 unsupported，原因说明了这一点。OceanBase 的 `ob_query_timeout`
  本来就停止写语句，不受影响。
- **只读账号不告警写超时**：逃生通道连接的账号不能写时，不再报告其写超时未在数据库侧强制。
  不能写指服务器处于 `read_only`/`super_read_only`，或 `SHOW GRANTS` 只有读权限。权限无法判断
  （例如授予了角色）时照旧告警。
- **服务端原因文本本地化**：能力声明、数据库侧限制、发布前判定与方案例外的原因带稳定的 code
  与参数（`core/reason`，集中登记），控制台按 code 显示中文或英文，未知 code 回退英文原文；
  日志、CLI、MCP 与兼容矩阵仍输出英文。管理 API 新增 `reasonDetail`、`useDetail` 与
  `Validation.notices`，原有文本字段不变。以下位置不再出现未翻译的英文原因：
  - 数据源连接详情；
  - 授权矩阵的权限提示；
  - 发布审核与方案预览的提示；
  - 方案中被拒绝的动作；
  - 能力键与用途。

## 性能与资源上限

- **MCP 事件存储**：超出容量时的淘汰由每次全量遍历求和，改为在按大小维护的堆上进行。小事件
  突发下，每次 Append 从约 7 µs 降到约 0.2–0.3 µs，见
  [热路径基准](../benchmarks/hot-paths.md)。被淘汰空的流保留编号，客户端重连拿到“事件已
  清除”，而不是错位的事件。
- **管理端登录失败表有界**：容量满时只淘汰退避已结束的条目。新用户名不再插入，改为共用一个
  溢出锁定条目，活跃的锁定和退避记录不会被名字洪泛挤掉。此前表可能无界增长，且清理时会重置
  退避历史。

## 控制台

- **同步实体**：实体列表新增“同步实体”按钮（有筛选时为“同步匹配的 N 个”），需要
  `admin:write`。流程分两步：
  1. **刷新元数据**：列出相关的库及其最近扫描时间，默认先扫描超过 1 小时未扫描的库，可跳过；
  2. **预览方案**：
     - 新增的列默认隐藏；
     - 删除数据库中已不存在的字段；
     - 按数据库更新主键、唯一键和表/视图类型；
     - 删除表已不存在的实体，并列出将删除的实体。

  方案只写入工作区，发布仍走审核流程。补充说明：
  - 运行时发现的缺失（未重新扫描的表）也会进入方案；
  - 行范围引用的列缺失时，不删任何字段，只给出需确认的例外（`rowColumnMissing`）；
  - 外键关系的差异只报告（`relationshipNew`、`relationshipStale`），不自动改写，因为配置里
    无法区分导入的关系和手写的关系；
  - 不可达数据源的实体和存储过程不参与同步。

  方案新增范围条件 `scope.entities`、同步规则 `sync.keys`，配置 MCP 同样可用。
- 实体页新增“允许修改主键”开关；用户页新增“客户端证书（mTLS）”编辑；过滤器编辑器支持
  取反条件组。

## 重构

- 行过滤的 subject 解析、请求过滤的别名与路径改名、条件字段提取，统一走
  `relalg.MapConditions` 和 `relalg.Fields`，不再各自手写遍历。
- 限额收紧统一为 `budget.Stricter`，0 及以下均表示不限。

## 迁移

1. **写工具**：省略 `tools` 的部署如需写入，显式开启：

   ```yaml
   tools:
     describeEntities: true
     readRecords: true
     aggregateRecords: true
     createRecord: true
     updateRecord: true
   ```

   写出 `tools` 块后未写的工具保持关闭，需列出全部要用的工具。
2. **租户与行范围下的写入**：
   - 依赖“create 可写任意租户”的调用会得到 `ROW_POLICY_VIOLATION`；
   - 隐藏的租户列由服务端填入，调用方无需提供；
   - 行范围的值用与列类型一致的写法：整数列写数字，不要写字符串 `"7"`。服务端按 IR 语义比较，
     类型不同视为不可比较而拒绝。
3. **修改主键**：确实需要的实体设置 `allowKeyUpdate: true`，否则改为先删除再创建。
4. **共享 token**：非 loopback 监听且 token 短于 32 字节时启动失败。用 `openssl rand -hex 32`
   生成新 token 并替换客户端配置；quickstart 示例的 token 已同步加长。
5. **mTLS**：配置了用户、且客户端只出示证书时，给对应用户写 `certSubjects`。暂时无法映射时，
   设置 `server.auth.tls.clientIdentity: default`。
6. **逃生通道**：`cost.enabled: false` 且开启 `tools.executeSql` 的部署，写
   `cost.sqlEscape.estimate: skip`；provider 不支持 EXPLAIN 时同样如此。
7. **扫描量未知的全表扫描**：对相关表运行 ANALYZE，让 provider 测出行数；或改用带索引的过滤；
   或把 `cost.maxScannedRows` 设为 0（不限）。
8. **数字**：整数列收到小数时返回 `INVALID_INPUT`；decimal 列按原值写入。依赖浮点舍入的调用
   需改为精确值。
9. **`X-MCP-Subject`**：代理传入对象或嵌套列表的属性需改为标量或标量列表。
10. **`readAfterWrite`** 超过 1 小时时校验失败，调低到 `1h` 以内。
11. **配置**：以下写法在加载时即被拒绝：空 `and`/`or`、条件多余的键、行过滤引用字段别名、字段
    别名重复。按报错改正，行过滤应写列名。
12. **配置存储**：打开时自动迁移到 schema 6。若报告多个 published revision，保留服务正在运行
    的那个，其余改为 `superseded` 后重新打开。

实施中另外发现并修复了三处：

- `store init` 与 MySQL/OceanBase 迁移不能重跑；
- 行过滤 `in` 列表中的占位符不解析；
- 控制台无法应用只删除实体的方案。

## 已知限制

- 经事务型连接池的 MySQL 连接，写超时仍需在数据库侧另行限制（DBA）。
- 只读判定只在 MySQL/OceanBase 上实现，OceanBase 的 `SHOW GRANTS` 格式未经独立验证，无法判断
  时照旧告警。
- 实体不可用的原因、数据源不可达时的驱动错误原文、`requireNativeLimits` 的校验错误与权限模拟的
  授权原因仍为英文。

- WITH CHECK 在服务端按 IR 语义求值，不模拟数据库排序规则。在大小写不敏感的排序规则下，
  否定条件（`ne`、`not_in`、`not`）可能与数据库判定不同。存储过程与 `execute_sql` 的写入不受
  此检查。
- 共享 token 只检查长度，不检查熵。
- 同步实体不改写关系，只报告差异；视图上声明的键不同步。
- 行过滤中 `in` 的 subject 列表属性为空时，语句在生成阶段失败（fail closed），不会返回空结果。
