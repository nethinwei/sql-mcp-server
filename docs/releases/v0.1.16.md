# v0.1.16

`v0.1.16` 让管理控制台在数千实体的配置下可用：此前实体列表、授权矩阵与可见性预览一次
渲染全部实体，可见性预览在 1 万实体时每次刷新传回约 10 MB。同版修复发布流水线的镜像
构建。

本版本没有 breaking 变更。

## 控制台分页

- **实体列表**：分页（每页 20/50/100/200，默认 50）；一页从某个命名空间中间开始时补上
  “数据源 · 库”标题。搜索、数据源筛选、页码与每页条数写在 URL 中（`?q=&ds=&page=&size=`），
  从实体详情返回时停在原处。
- **授权矩阵**（角色、用户页）：按实体分页，同一实体的多条授权不跨页；授权按实体预建
  索引，不再逐行扫描全部授权。表头的整列勾选仍作用于全部匹配的实体，不只当前页。
- **可见性预览**（角色、用户页与权限模拟）：改用服务端分页（见下），可按实体 ID 搜索；
  “只看可访问”在服务端筛选。搜索匹配完整实体 ID（`数据源.库.名称`），此前匹配简称。
- **版本历史**：每次加载 50 个，“加载更多”以增大的 limit 整体重取，期间新增的版本不会
  造成缺口；已发布版本不在已加载范围内时取自服务状态，差异的比较基准不变。
- **审核摘要**：用户获得/失去/变更的授权、实体增删、字段变化超过 30 项时折叠，可展开。
- **总览“最近版本”**：长说明截断显示（悬停看全文），版本号与时间不再被挤压。

## 管理 API

- 新增 `visibilityPage(input: VisibilityInput!, filter: VisibilityFilter, offset: Int = 0,
  limit: Int = 50): VisibilityPage!`。服务端仍用同一个离线授权器评估全部实体，返回
  `total`、`reachable`（有允许或需选择字段的动作）、`needsFields`、`matched` 与适用的
  `actions`，`items` 只含当前页（`limit` 上限 200）。`filter.search` 按实体 ID 子串匹配
  （忽略大小写），`filter.reachableOnly` 只保留可访问实体。权限与 `visibility` 相同：
  `admin:read` 且不受数据源限定。
- `visibility` 不变。1 万实体实测：`visibilityPage` 每页约 2 KB（gzip）、约 0.2 s，
  `visibility` 约 10 MB。

## 发布流水线（修复）

- 镜像的控制台与 Go 构建阶段改在构建平台上运行：控制台在各平台都是相同的静态文件，Go 按
  `TARGETOS`/`TARGETARCH` 交叉编译，多架构构建不再经 QEMU 模拟。`v0.1.15` 的镜像任务曾因
  arm64 下 Node 在模拟中崩溃（SIGILL）而卡到 6 小时上限。镜像任务另设 45 分钟超时。

## 迁移

无需迁移。直接调用管理 API `visibility` 的脚本不受影响；需要分页时改用 `visibilityPage`。

## 已知限制

- 在授权矩阵中一次勾选上万个实体后，可见性预览约 3 秒以上才更新；耗时在把上万条授权
  写回工作区，不在可见性查询。
- 实体列表的数据库注释仍在会话内一次取全部表（1 万张表约 1 s、190 KB，按会话缓存），
  以便搜索覆盖注释。
- 授权矩阵与可见性预览的页码不写入 URL。
