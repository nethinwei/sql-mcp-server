# v0.1.21

`v0.1.21` 是一个加固与新能力并行的版本。它包含两块工作：

- 一批面向生产的能力与约束：PostgreSQL 只连接 11–18、继承与分区的级联归入授权、
  成本模板 fingerprint 升为 `fp:v4:`、结果截断与游标、缓存总字节上限、语句超时的
  稳定分类；
- 发布前的四轮独立代码审查（数据面、控制面、配置与规划、控制台、评测与发布门禁），
  共处理约 70 项发现，包括脱敏连接列的关系展开、`expand` 扇出绕过字节上限、中断
  语句被当作可重试超时、工作区空键、登录/登出 CSRF、发布门禁等。

本版本**有 breaking 变更**，见[迁移](#迁移)。审查方法与结论见
[Review 处理](#review-处理)。

## 安全

- 任一侧连接列被脱敏的关系不能再用于 `expand`、跨关系过滤/排序与 `exists`：子行会
  带出与父行相等的原值。拒绝发生在发出任何查询之前。
- PostgreSQL 分区表与传统继承（`INHERITS`）上的外键级联与 trigger 归入被暴露实体的
  授权范围：删除父表行不再经数据库级联删到未暴露的数据（违反 I-6）。
- 关系名不能再与字段路径、SQL 别名混淆（含 `.`、`_`、`x<数字>` 的关系名在加载时
  拒绝）；实体 `roles` 中的空角色、`server.role` 写成用户 principal 一并拒绝。
- 管理面：登录要求 JSON 来源且失败表溢出不再锁死全部管理员；`Revision` 与
  `Workspace` 的内容字段统一要求 `admin:read`；会话 Cookie 的 `Secure` 跟随
  `server.publicURL`；`/admin/logout` 只在有效会话上生效；SSE 事件流每 30 秒复核账号。
- 审计：实体引用解析不到时按最保守方式脱敏，不再把被 mask 字段的值原样写入审计。
- 配置：`version` 契约标记在加载时校验；`sslpassword` 与旧式 `database:` 段纳入
  密钥检查；同一份配置的校验错误顺序稳定。

## 修复

数据面：

- `expand` 的子行被多个父行共享时按实际返回次数计入 `cost.maxBytes` 与预算
  `maxReturnedBytes`；一批子行触顶以 `BUDGET_EXCEEDED` 失败，不再静默丢子行。
- 数据库在自己的语句超时处停住的语句报 `STATEMENT_TIMEOUT`（可重试）；被中断的
  写入、存储过程调用、提交与 `execute_sql`（任一模式）报 `OUTCOME_UNKNOWN`，
  不再提示“未生效、可重试”。
- 结果中的 NaN/±Infinity 以字符串 `"NaN"`、`"Infinity"`、`"-Infinity"` 返回。
- 聚合的分组字段若是别名、其列名与聚合列同名时拒绝；无谓词的 `Select` 在 codegen
  拒绝；聚合谓词按配置的 `cost.maxINListSize` 判断。
- 引用解释器与 codegen 对非法 `Limit` 的拒绝集合一致；`LIKE` 支持 `\` 转义。

Provider 与数据库侧：

- MySQL/OceanBase：`BIGINT UNSIGNED` 在文本/二进制协议下读为同一类型；DSN 未设
  `timeout` 时拨号限时 10 秒，配置语句超时后读超时为其加 10 秒；被 KILL QUERY 的
  连接在事务内拒绝后续语句与 COMMIT/ROLLBACK；只有 `clientFoundRows` 参数本身
  （而非密码中的同名文字）会关闭匹配行计数。
- PostgreSQL：DSN 显式 `connect_timeout` 与 `PGCONNECT_TIMEOUT` 不再被覆盖；分区表
  全扫描按被扫描分区合计、按 schema 匹配表、识别并行位图堆扫描；统计新鲜度检查
  计划读取的每张表；`json`/`jsonb`/`xml` 返回原文；domain 默认值、`NOT VALID` 非空
  约束、分区外键与 11–13/18 的 EXPLAIN 差异逐项修正。

控制面与配置：

- 工作区：对象中的空键不再被当作列表元素（冲突不再静默关闭、对象不再变成数组）；
  三方合并对双方新增的对象按键合并；重复合并同一草稿不写入新版本；改名后回退会
  清除改名记录；`resetWorkspace`/`updateWorkspace` 只接受发布过的修订。
- 批量配置：同步键时列不是实体字段的键不写入（`keyNotField`）；外键目标实体缺少
  连接列时不生成关系（`relationshipDropped`）；被删除表的同步变更与例外从报告中
  移除；同步清空授权字段时报告 `grantFieldsEmptied`；通配授权随新增列加宽且保持
  幂等；扫描批次按 `requestKey` 与管理员区分。
- 配置存储：目录列表与 schema 改为原子 upsert；待处理状态同样；批次列表只读计数、
  详情按批次读取；schema 升级跨进程串行。

控制台：

- 授权范围编辑器按身份定位，不再因并发写入改写错误的 grant；回退清除 `renamedFrom`；
  `?token=1` 在用户载入后才铸造 token；批量列切换 O(E+G)；扫描批次合并不丢并发批次；
  实体变更跳转到正确的路由；窄屏下资源限制、版本历史与授权对话框保留行距。

## 迁移

1. **PostgreSQL 版本**：只连接 11–18；10 及以下、19 及以上与协议兼容库（Hologres、
   Greenplum、Redshift、CockroachDB、openGauss/GaussDB、YugabyteDB）在连接时拒绝。
2. **继承与分区**：有子表的父表按派生关系处理，键取实体配置；分区/继承的级联与
   trigger 归入其祖先表——依赖“级联写到未暴露表”的部署需重新审视授权。
3. **成本模板**：`fp:v3:` 在加载时拒绝，按本版本重新采集为 `fp:v4:`；
   `datasource:SQL` 与精确 SQL 模板对带 `LIMIT`/`NULLS LAST` 的语句不再匹配，需逐条复核。
4. **NULL 比较**：`eq`/`ne`/`gt`/`gte`/`lt`/`lte`/`like` 与 `null` 比较返回
   `INVALID_INPUT`；判断 NULL 用 `is_null` / `is_not_null`。
5. **配置**：YAML 只能有一个文档；`database:` 与 `databases:` 同时出现且不是同一
   数据源的导出形式时拒绝；空角色、含 `.` 的关系名、空字符串列表元素拒绝。
6. **参数校验**：`aggregate_records` 需 `aggregates` 或 `groupBy`，`sum`/`avg`/`min`/`max`
   需 `field`，`in`/`not_in` 需非空列表；批量配置方案 `exclude` 未知表时拒绝。
7. **`rowsAffected`**：MySQL/OceanBase 改为匹配行数，与 PostgreSQL 一致。
8. **管理 API**：`resetWorkspace`/`updateWorkspace` 只接受发布过的修订，载入任意修订
   改用 `loadRevision`；带 `renamedFrom` 的写入必须同时写出旧项删除。
9. **迁移工具**：配置存储打开时自动升级 schema；若报告多个 published revision，
   保留服务正在运行的那个，其余改为 `superseded` 后重新打开。

## Review 处理

发布前对 `release/v0.1.21` 做了四轮审查（第 9–12 轮），每轮由全新的独立评审上下文
执行，修复后再由下一轮复审：

| 轮次 | 范围 |
| --- | --- |
| 9 | 数据面、控制面、配置与规划、控制台、评测与发布门禁 |
| 10 | 数据面安全与 driver 语义、控制面、控制台与文档 |
| 11 | 修复本身的边界、发布门禁、配置存储 |
| 12 | 收尾：确定性、raw 语句、`expand` 边界、发布流程 |

共 13 个提交。最后一轮独立复审返回 `No findings`；随后 `make ci` 通过（覆盖率 84.9%）。

## 已知限制

- 全表扫描的表大小仍取所涉各表中最大的一个（分区按所属表求和），多表计划低于实际
  扫描总量；`cost.maxScannedRows` 是估算上限，不是精确计量。
- `skip` 的逃生通道估算在 EXPLAIN 失败时按配置决定拒绝或跳过；逃生通道不做字段与
  行治理、不脱敏。
- MySQL/OceanBase 的 `rowsAffected` 依赖 `clientFoundRows=true`；DSN 显式关闭时以
  数据库语义为准。
